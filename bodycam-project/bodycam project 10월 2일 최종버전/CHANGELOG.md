# 버전별 기록 (CHANGELOG)

"확인" 표시의 뜻
- **보드 확인**: 실제 XIAO ESP32S3 Sense 보드와 라떼판다에서 동작을 확인함
- **PC 시험**: 개발 PC에서 가짜 바디캠(파이썬)으로 시험함. 실제 보드로는 아직 확인 안 됨
- **문법 검사만**: 컴파일과 동작은 아직 확인 안 됨

### 펌웨어 보드 설정 (XIAO_ESP32S3)
- Board: XIAO_ESP32S3 / PSRAM: **OPI PSRAM** / USB CDC On Boot: **Enabled**
- Partition Scheme: **Default with spiffs (3MB APP/1.5MB SPIFFS)** (기본값, 다른 보드의 "Huge APP"과 다름)
- 라이브러리: PubSubClient (Nick O'Leary), WebSockets (Markus Sattler)

### 서버 업데이트 절차 요약
1. 윈도우에서 `scp 파일 panda@lattepanda:~/bodycam-server.zip`
2. 라떼판다에서 **풀기 전에** 새 파일인지 확인: `unzip -p ~/bodycam-server.zip bodycam-server/app/main.py | grep -c "TIME_VALID_MS"` → 3 (1.4 기준)
3. `cd ~ && unzip -o bodycam-server.zip && sudo systemctl restart bodycam`
4. 설치 후 확인: `grep -c "TIME_VALID_MS" ~/bodycam-server/app/main.py` → 3 (1.4 기준)

## 해결된 것 (2026-10-02)

- **ack 문제**: 서버 1.3 + 펌웨어 0.2.5에서 `[ws] 수신:`과 `업로드 완료` 확인 (cam01, cam02, cam03 모두). cam01은 10:03:00 녹화, 세션 10:03:10보다 10초 앞에서 시작. 1.3과 0.2.5 중 어느 쪽이 결정적이었는지는 구분 안 됨.
- **시간 동기화 전 녹화 날짜**: 1.3까지는 1970-01-01로 저장됨. 서버 1.4로 해결 (cam03 09:52:36 녹화로 확인). 1.4 이전에 만든 1970-01-01 녹화는 그대로 남아 있음.
- **MP4 확인**: cam02 09:33:48 녹화. 세션 시작 09:33:58보다 10초 앞에서 시작(사전녹화 확인), 25초, 9fps, 소리 들림, 화면 방향 정상.

## 아직 해결되지 않은 것 (2026-10-02 기준)

1. **보드가 스스로 재시작된 원인**: `rst:0x3 (RTC_SW_SYS_RST)`가 한 번 관찰됨. 원인 미확인. 펌웨어 0.2.5의 `[재시작 이유]` 출력으로 확인 예정.
2. 재시작 직후 SD카드를 못 찾던 현상: USB 전원을 완전히 껐다 켜면 복구됨. 0.2.5의 재시도로 완화 예정(미확인).
3. 재시작 이유 `기타 (코드 11)`: 펌웨어 업로드 직후 cam01에서 나옴. ESP-IDF 기준 11은 USB에 의한 재시작(`ESP_RST_USB`)으로 업로드 후에는 정상으로 **추정**. 0.2.5의 이유 목록에 없어 "기타"로 표시됨. 다음 펌웨어에서 이름 추가 예정.
4. 라떼판다 USB 와이파이 동글(RTL8821CU)이 핫스팟을 오래 켜 두면 멈추는 일이 있음 (껐다 켜면 복구). MediaTek 동글 교체 예정.
